# LP着座とキーキャップ隙間の再検討

確認日: 2026-11-08。この資料はクラウドv6時点の比較検討。その後、[着座修正v7](lp-seating-revision.md)を反映した。以下の「現行Z=4.50」は比較時点を指す。

## 寸法基準の訂正

以前の調査で6.40 mmを「軸上端からPCB側着座面」と記したのは誤り。[メーカー図面CPG1353D01D01-24](https://www.kailhswitch.com/uploads/15927/files/CPG1353D01D01-24-data-sheet.pdf)の1ページ目を画像で再確認すると、終点はフランジ下面だった。図面全体と寸法の拡大をdocs/images/spring-mini-*-review／detail.pngに保存した。

同じ図面の5.70と3.50は、上側の小さな段の同一面から、それぞれ下側ハウジング底面とフランジ下面までの寸法。公称値では次の関係になる。図面の無指示寸法公差、実物の着座隙間、PCB版は別途確認が必要であり、加工公差込みの確定値ではない。

| 基準 | 公称値 mm |
| --- | --- |
| フランジ下面からハウジング底面 | 5.70 − 3.50 = 2.20 |
| 軸上端からハウジング底面 | 6.40 + 2.20 = 8.60 |
| 公開PCB上面 | Z=1.60（現物版は未確認） |
| 底面をPCB上面に着座させたフランジ下面 | Z=3.80 |
| 同じ条件の非押下時軸上端 | Z=10.20 |
| 最大ストローク3.05を引いた軸上端 | Z=7.15 |

現行天板上面Z=4.50は、公称のフランジ着座面より0.70高い。PCBに着座したスイッチを表すなら、この天板位置は修正対象。天板に着座させればスイッチ底面がPCBから0.70浮く関係になるため、接点挿入や保持が成立するとは扱わない。

既存の14 mm角ボックスはフランジ・爪を表さず、以前の29ソリッド干渉0件ではこの問題を検出できない。上側最大外形15 mmと開口14.1 mmの関係を含め、着座フランジを追加した検査が必要。

## キーキャップ押下時の条件

キャップの最も低い点が、非押下時の軸上端より下がる量をDとする。Dはキャップ高さ3.94そのものでも、ステム挿入深さ単独でもなく、底形状・取付位置を合わせた値。実物値は未確認。

公称値と最大ストロークに基づく隙間は `7.15 − D − 天板Z`。天板Z=3.80なら `3.35 − D`、現行Z=4.50なら `2.65 − D`。ここに寸法公差・傾き・ケース変形の余裕は含めていない。

| 仮のD mm | 現行Z=4.50の隙間 | 着座候補Z=3.80の隙間 |
| --- | --- | --- |
| 2.0 | 0.65 | 1.35 |
| 2.5 | 0.15 | 0.85 |
| 3.0 | −0.35 | 0.35 |
| 3.5 | −0.85 | −0.15 |

例えば仮の目標隙間0.30を置く場合、Z=3.80ではD≤3.05が必要。ただし0.30は比較用の設計仮定で、メーカー指定ではない。キーキャップを直方体3.94として重ねるだけで押下干渉を判定しない。

## XIAOカバーの平面比較

23キーすべての18.8角の仮包絡（公称18.1＋片側0.35）とカバー矩形の距離を再計算した。公開基板のキー中心・回転を使用し、辺と頂点の距離を求めている。

| カバー案 | 最小隙間 mm | 最寄りキー |
| --- | --- | --- |
| 現行 X±9.9、Y−20.95〜3.0 | 0.11934 | SW17 |
| 幅だけ18.6へ縮小 | 0.13600 | SW21 |
| 幅18.6、Y−20.35〜2.4（四辺各0.6縮小） | 0.71934 | SW17 |

四辺縮小案は平面比較の候補に留める。壁厚0.8を維持すると側壁内側はX±8.5となり、現行MCU主部X±8.89に入り込む。低い側壁を残した単純縮小は不成立。側壁下端をMCU主部上面Z=4.87より上へ上げる案、局所的な逃げ、固定用の脚をキーから離した位置へ設ける案を比較する。背面の覆い、USBアクセス、組付け方向も再検査する。0.35は軸の横変位に由来する仮余裕で、キャップ全体の最大傾きを保証しない。

## 次の形状修正

1. 変更前チェックポイントを保持し、着座フランジを含むスイッチ参照を作る。図面公差と基板着座を明示する。
2. 天板Z=3.8を公称比較の出発点とし、厚さ1.2の爪保持、PCBとの距離、フランジ接触を検証する。外周・ねじボス高さまで一律に下げない。
3. キャップDを変数にした押下包絡とカバーの干渉を検査し、四辺縮小＋下端逃げのカバー候補を比較する。
4. 固定、USB、脱着経路を検証してから現行CADを更新する。

再計算: `python scripts/analyze-lp-seating.py`。全キー・高さ感度の数値は[検討JSON](lp-seating-clearance-study.json)。この計算はFusionや元CADを書き換えない。
